## Provenance note

`results.json` records `working_tree_dirty: false` for the timed scenarios: the
tree was clean when measurement began. The delegated census and competitive
harnesses report `dirty: true` in their own JSON because this evidence directory
already existed, untracked, while they ran. They record the same commit and the
same binary SHA-256 above. No source file differs between those runs.

## Headline results (this commit, this host)

- CPU-heavy transform: 333.1 ms direct, 8.8 ms warm hit (about 37x), 374.6 ms cold trace.
- `/bin/true` floor: 0.83 ms direct, 6.41 ms warm hit. Short commands lose.
- `gzip -9` over 4 MiB: 117.2 ms direct, 289.3 ms warm hit. Replaying compressed
  stdout costs more than recompressing; this is a retained loss.
- 10-run ETL session: 89.0 ms direct, 125.3 ms with one trace and nine hits.
- 64 MiB output: 142.8 ms direct, 193.3 ms warm hit, 588.9 ms cold trace.
- Mutated input: 15.7 ms direct, 31.6 ms after a required deopt; zero stale hits.
- 8 concurrent runs: 72.4 ms cold, 22.1 ms warm, all processes successful.
- Census: 1 of 32 unmodified real-world commands reached a verified reuse
  (eligibility 0.032); 30 were refused, 1 was blocked on a missing tool.
- Make wins identical rerun wall time (1.98 ms vs 33.99 ms) and returns
  **WRONG** output for an mtime-preserved edit and a corrupted output file,
  where TraceJIT recomputes correctly.

Nothing here is a general speedup claim. Negative results are intentionally kept.
