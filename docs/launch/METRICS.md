# What to measure

Check these manually. Do not add telemetry to the binary. Do not optimize the project for the first list.

## Attention

- GitHub stars, clones, and unique visitors, from the repository traffic tab if it is enabled.
- Release download counts for the archive.
- Views on the Show HN thread and any other post you actually made.
- Where a visitor said they came from, only when they said it.

These numbers say the post was seen. They do not say the tool works.

## Use

- Issues that include a command, a classification, and a commit.
- Pull requests from someone other than the maintainer.
- Comments that reproduce `./scripts/demo.sh` or the benchmark harness, including reproductions that disagree with the published median.
- Questions about a specific guard, syscall, or `PROVEN` condition.

A star with no issue is attention. A failing fixture is the useful event.

## What not to do

- Do not add a badge that asks for a star.
- Do not count a forced repost as growth.
- Do not change the safety default because eligible commands produce better screenshots.
- Do not treat a faster synthetic transform as adoption.

Review the two lists once at the end of the 30 days. Write three sentences in `PROJECT_STATE.md` about what people tried to run. Ignore the star count in that paragraph.
